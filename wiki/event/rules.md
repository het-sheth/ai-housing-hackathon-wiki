# Rules, judging and submission

The Participant Packet was read in full: 14 pages. Rules below are packet requirements unless identified otherwise.

## Team and build window

Teams have 1-5 participating members, aged 18 or older. Select one track and submit one project. Building begins September 26, 2026 at 9:00 a.m. ET. Submission closes September 27 at 11:59 p.m. ET, with no extensions. Pre-event research and sketching are allowed; prior project code is prohibited. The packet separately allows libraries, frameworks, open-source code, public data and APIs with disclosure (pp. 4-7).

The submission repository must be public, remain public for prize eligibility, and retain commit history beginning at kickoff. This repository organizes research using an existing wiki template; the team will create a separate application repository for its event build. The packet does not specifically settle the treatment of generic starter generators or research wiki templates. Record all tools used and resolve any consequential interpretation with organizers.

## Submission checklist

1. Team/member details, selected track, title and description.
2. Public working code repository and documentation.
3. A public 3-5 minute demo video recorded during the event; identify working and mocked portions.
4. Dataset/source citations and AI tool disclosure, including how tools were used.
5. Limitations statement and age/code-date attestation.
6. Submit through the form before the hard deadline (pp. 8-9).

## Judging

Six criteria, with no numeric weights provided: Problem Value; User Fit & Usability; Technical Execution; Data & AI Integrity; Actionability; Continuation Potential. At least three judges review each project (p. 9).

Tools must provide decision support, with human review for consequential decisions. Do not present binding legal, financial or zoning advice.
