## Recommended next move

Make one manual worked example before choosing an implementation scope. Use a documented Pittsburgh project as a validation precedent, not a property advertised as available. The Lanark Street/Fineview CLT effort provides zoning and financing history, but its public project description is not a current parcel-specific pro forma. The historic 21 Lanark rowhouse in the advocacy article is a comparison property, not interchangeable with the CLT development parcels. See [case details and dated sources](pittsburgh-case-check-2026-09-26.md).

1. Confirm one exact parcel and one proposed housing concept. Record whether the scenario is hypothetical, historical, or an actual documented proposal.
2. Write the answer to what the current rules appear to allow, citing current code and the parcel geometry. Do not reuse 2023/2024 zoning calculations without checking subsequent amendments.
3. List the minimum financial inputs for this concept: acquisition, site work, hard costs, soft costs, financing/carry, sale proceeds or rents, and any affordability restrictions or subsidy. Mark each sourced, practitioner-supplied, or unknown. Do not insert invented costs or treat nearby asking rents as achieved rents.
4. Show which missing answer prevents the next decision and who could provide it. Draft a concrete output for SME review, without claiming a validated score or recommending purchase.
5. Select a product boundary based on that review. If reliable comps are the bottleneck, test a comp-evidence workflow. If assumptions are available but comparisons are difficult, test transparent scenarios. If neither financial input set is available, build a bounded constraint-and-next-action screen and explicitly leave financial feasibility unassessed.

Do not add all three financial options to the weekend scope. Do not call a coverage percentage a Development Ease Score. Locality, citations and PDF export alone are insufficient differentiation given Rescope's documented features.
