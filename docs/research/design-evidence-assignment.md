# Design evidence research assignment

Contribution: Rushi Patel's September 26, 2026 product-design discussion, consolidated September 27. This is a reconstruction of substantive work, not a timestamped transcript. Commit timestamps record publication work. Status: research assignment, not completed validation.

## Copyable assignment

Research a small Pittsburgh housing feasibility navigator. No private repository access is needed. Our candidate user is a project lead at a small nonprofit developer deciding whether to spend more on a property. Our candidate interaction compares two housing proposals on one site and exports requirements, uncertainties and next actions. Repair/remodel versus expansion is a hypothesis, not a fixed specification.

Gather original evidence that can change a design decision. Prefer actual forms, acquisition criteria, feasibility scopes, pre-application packets, project histories and public practitioner statements. Do not produce another general housing-market survey.

1. Reconstruct the workflow from opportunity to first diligence expenditure. Identify actor, decision, known inputs, missing inputs, existing artifact and next recipient at each step. Separate observed practice from inference.
2. Find documented cases where scope changed after a zoning or site finding. Record the original goal, proposal, discovery, reviewer, revised proposal and documented consequence. Explain transfer limits between multifamily, infill and rehabilitation.
3. Extract the fields of actual early-screening briefs. For each field, state who uses it, the decision it affects, its source, whether it is knowable at that stage and how to represent unknown values.
4. Map the minimum authoritative data: parcel identity, jurisdiction, boundary, zoning, permit history, lawful-use evidence and relevant site constraints. Record endpoints, resource/layer IDs, field definitions, join keys, coordinate systems, dates, access and reuse terms. Distinguish catalog discovery from successful record retrieval and validated joins.
5. Trace the minimum current rules for one narrow comparison using primary authorities, dependencies and exceptions. Identify which inputs require applicant evidence or professional interpretation. Do not infer project permission from mapped zoning.
6. Find official public contact routes for relevant practitioners. Draft questions; do not send messages. If interviews are unavailable, use public artifacts and explicitly preserve the unanswered questions.
7. Seek disconfirming evidence: unavailable early-stage inputs, duplicate reports, comparisons that change no action, or financial dependencies that prevent the intended decision. Recommend a smaller product if warranted.

## Required return format

| Artifact | Required contents |
|---|---|
| Source register | ID, title, organization, URL, date, geography, project type, page/timestamp, access date, limitations |
| Evidence records | Evidence ID, source ID, extracted fact/short excerpt, context, evidence type, uncertainty, design question |
| Workflow | Step, actor, decision, inputs, current tool/artifact, missing information, next recipient, evidence IDs |
| Brief gap audit | Missing field, decision affected, source, early availability, unknown behavior, now/later priority |
| Data matrix | Endpoint, fields, identifiers, joins, freshness, authority boundary, actual verification status |
| Design synthesis | User, decision moment, comparison, requested inputs, fetched data, outputs, export, deferred scope, failure cases |

Save small relevant raw responses with exact queries and retrieval timestamps where permitted. Preserve leading zeros. Avoid unnecessary owner/contact fields. Do not mistake a network error for zero records or missing records for absence of constraints.

Finish with the three highest-value missing datapoints and what evidence would change the recommendation. More evidence is useful only when it improves a decision. Never manufacture interviews, endorsements, estimates, demand or time savings. Keep factual extraction separate from interpretation, private material out of public outputs, and financial feasibility unassessed without credible inputs.
